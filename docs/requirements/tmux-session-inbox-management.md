# tmux 会话型联系人与会话管理需求

## 背景

当前 Android 客户端已经能展示多个 agent 会话，但仍有几个影响日常使用的问题：

1. 联系人名称仍偏向 bridge 或 agent 类型，不是用户真正关心的 tmux 会话名。
2. 历史离线会话会残留在首页，容易和当前在线会话混淆。
3. 会话页仍带有 `You`、`Agent` 这类偏协议层的标签，不够像日常 IM。
4. 首页缺少“新增会话”入口，无法直接创建新的 tmux-backed agent 会话。

本需求用于把当前系统进一步收敛为“个人私有 Agent IM”，让联系人、会话和实际 tmux 工作流保持一致。

## 目标

### 1. 联系人名称改为 tmux 会话名

- Android 首页联系人卡片主标题应展示 tmux 会话名。
- 会话页顶部标题也应展示 tmux 会话名。
- tmux bridge 注册到 hub 时，`displayName` 应默认使用 tmux 会话名。

### 2. 历史离线会话应可清理，并默认不再干扰首页

- 已离线的历史 agent 会话不应继续长期占据首页联系人列表。
- Hub 应支持清理离线会话及其时间线事件。
- Android 客户端在接收到离线 delta 时，应从首页联系人列表中移除对应历史联系人。

### 3. 消息头更接近 IM

- 用户自己发出的消息不显示 `You` 标签。
- 对端消息不显示泛化的 `Agent` 标签。
- 对端消息头应显示真正的 agent 名称，例如 `codex`；若后续支持其他 agent，则显示对应实际 agent 名称。

### 4. 首页支持新增会话

- 首页应提供“新增会话”入口。
- 新增会话时至少可配置：
  - 使用哪个 agent
  - 会话名称
- 新增的会话本质上应对应一个新的 tmux session。
- Hub 应负责创建 tmux session 并拉起对应 bridge，使该会话自动出现在联系人列表。

## MVP 范围

- 当前机器至少支持通过首页创建 `codex` 会话。
- agent 选择列表可根据主机环境动态返回；若只有 `codex` 可用，则仅展示 `codex`。
- 新创建的会话成功后，应自动出现在 Android 首页，并可直接进入聊天。

## 非目标

- 本阶段不做完整多 agent 插件系统。
- 本阶段不做复杂会话模板、启动参数编辑器或环境编排。
- 本阶段不做历史会话归档检索。
