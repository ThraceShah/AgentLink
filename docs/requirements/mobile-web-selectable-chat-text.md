# 移动 Web 聊天文本选择需求

## 背景

移动 Web 聊天消息此前通过点击整条消息复制全文。该交互会与浏览器原生文本选择冲突，用户拖选局部文字时容易触发复制、丢失选区或出现非预期多选。

## 目标

- 聊天消息正文必须支持浏览器原生文本选择。
- 用户拖选消息局部文本时，不应触发整条消息复制。
- 用户保持聊天区文本选区时，WebSocket 消息或定时轮询刷新不应重建聊天时间线并清空选区。
- 复制整条消息应改为显式按钮操作。
- 消息中的链接、代码和长文本仍需保持可选择、可换行且不撑破视口。

## 非目标

- 不实现自定义文本选择控件。
- 不改变消息渲染的数据来源和时间线合并逻辑。
- 不移除审批、附件等消息上的操作按钮。

## 验收标准

- 普通消息正文可用鼠标或触摸选择局部文字。
- 点击消息空白区域不再复制全文。
- 保持局部文字选中超过一个轮询周期后，选区仍然保留。
- 每条普通消息提供 `Copy` 按钮用于复制整条可见文本。
- `node --check apps/mobile-web/app.js`、`npm test`、`npm run build` 通过。
