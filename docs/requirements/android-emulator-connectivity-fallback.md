# Android 模拟器连接回退需求

## 背景

Android 客户端当前默认将 hub 地址设置为 `http://10.0.2.2:8787`，这适合多数模拟器访问宿主机的场景。

但在部分无界面或受限的 emulator 环境里，`10.0.2.2` 到宿主机的链路并不稳定，开发者往往会改用：

- `adb reverse tcp:8787 tcp:8787`
- 应用内连接 `http://127.0.0.1:8787`

如果客户端只尝试单一地址，会导致明明已经具备可用转发链路，界面仍显示连接失败。

## 目标

- 在 Android Emulator 环境中，提升 hub 连接的容错性。
- 保持普通真机、局域网和 Tailscale 场景下的现有行为不变。
- 不引入复杂自动发现逻辑。

## MVP 范围

- 用户配置 `10.0.2.2` 地址时，客户端在 emulator 环境下可按顺序尝试：
  - `http://10.0.2.2:<port>`
  - `http://127.0.0.1:<port>`
- 仅在 emulator 环境启用该回退。
- 一旦回退地址连接成功，应保存成功地址，避免下次重复失败。

## 非目标

- 不为真机自动猜测私网 IP。
- 不实现 mDNS、广播发现或 zeroconf。
- 不自动创建 `adb reverse`。
- 不在当前阶段引入 HTTPS 自动协商。

## 验收标准

- 在常规模拟器环境中，`10.0.2.2` 能继续正常连接。
- 在启用了 `adb reverse` 的无界面模拟器环境中，即使 `10.0.2.2` 失败，客户端也能回退到 `127.0.0.1` 成功连上 hub。
- 连接成功后，agent 列表和时间线能正常显示。
