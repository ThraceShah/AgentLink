# 会话排序与消息模型标签需求

## 背景

当前 Android 客户端已经具备多会话收件箱和会话页，但仍存在两个影响日常使用体验的问题：

1. 会话卡片显示的时间会被在线保活行为干扰，不能准确代表最后一次真实对话时间。
2. 会话卡片未按“最近有新消息的会话优先”排序，不符合 IM 使用习惯。
3. 会话页中的消息标签仍然偏向“agent/provider”级别，而不是消息实际对应的模型。

这些问题会削弱“个人私有 Agent IM”的核心使用感，使首页更像状态面板而不是消息收件箱。

## 目标

本次功能需要完成以下能力：

1. 首页会话卡片显示“最后一次真实对话时间”，而不是当前在线时间。
2. 首页会话卡片按最新真实对话时间倒序排列。
3. “真实对话”至少包括：
   - 用户发送的文本消息
   - agent 返回的文本消息
   - 需要用户输入/审批的消息
   - 产物/图片消息
4. 心跳、上线、下线、运行中、完成等系统性事件不应污染会话排序时间。
5. 会话页中，用户消息不再显示 `You` 标签。
6. 会话页中，agent 消息标签显示该条消息对应的实际模型名，例如：
   - `gpt-5.4`
   - `glm-5`
   - `claude-sonnet-4.6`
7. 若同一会话中历史消息来自不同模型，界面应能按消息粒度准确展示。

## 工程判断

为保证历史消息准确性，模型信息不能只挂在 agent 当前状态上，必须固化到每条消息事件中。

为保证首页排序稳定性，排序依据不能直接使用 agent 在线时间或心跳时间，必须基于消息时间线重新推导“最后一次真实对话时间”。

## 验收标准

1. 同时存在多个会话时，最近有用户或 agent 新消息的会话排在最上方。
2. 长时间在线但没有新消息的会话，不会因为心跳保活跳到最上方。
3. 用户发送消息后，对应会话会立即上移到顶部。
4. agent 回复后，对应会话时间与排序再次刷新。
5. 会话页中用户消息不显示 `You`。
6. 会话页中 agent 消息显示实际模型标签。
7. 同一会话里若前后两条消息模型不同，界面能分别显示对应标签。
