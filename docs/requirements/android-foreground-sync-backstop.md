# Android 前台会话同步兜底需求

## 背景

当前 Android 客户端已经有：

- 前台 WebSocket 实时链路
- 后台前台服务通知轮询
- 前台恢复时的主动刷新

但实际使用中仍出现：

- 后台通知已经收到 agent 回复
- 前台聊天窗口没有及时出现同一条消息

这说明前台 UI 仍然可能遇到“WebSocket 表面在线、实际消息不同步”的情况。

## 问题判断

当前前台在 `socketState == CONNECTED` 时，会停止常规轮询。

因此一旦出现以下情况：

- WebSocket 假活
- WebSocket 消息没有及时送达 UI
- 前台恢复刷新时机不稳定

前台界面就可能停留在旧状态，而后台通知服务已经拿到新事件。

## 目标

- 即使前台 WebSocket 显示为已连接，前台 UI 也应保留一条轻量同步兜底
- 让会话页和通知服务最终保持一致
- 降低“通知到了但聊天窗口没刷新”的概率

## 方案

推荐保留：

- `WebSocket 为主`
- `轻量 HTTP bootstrap 同步为兜底`

具体策略：

- 不再在 `CONNECTED` 时完全停止前台轮询
- 改为在连接正常时使用更低频率轮询，例如每 3 秒一次
- 断线或回退模式下继续使用更高频率轮询

## 设计判断

这不是把系统退化成“纯轮询 IM”，而是承认：

- 前台实时链路用于体验
- 轻量同步链路用于一致性兜底

对于个人私有 Agent IM，这样的工程取舍比“极端坚持纯实时”更实用。

## 验收标准

- 前台打开会话时，即使 WebSocket 状态显示为 `Live`，仍会保留低频同步
- 后台通知出现后，用户回到聊天界面时，新消息可以在短时间内自动出现
- 不需要完全杀进程重启 App
- 使用本机 Android 模拟器完成自测
