# Android 通知与会话 UI 一致性修复需求

## 背景

当前 Android 客户端已经支持后台系统通知，但出现了一个一致性问题：

- 后台通知服务已经收到 agent 新消息并成功发出系统通知
- 用户重新回到 App 后，当前会话页不一定立刻出现这条新消息
- 往往需要完全退出并重开 App，界面才会刷新

这会造成“通知和会话内容不一致”的错误体验，必须修正。

## 问题判断

当前通知是由后台前台服务通过轮询获取并发出的，而前台 UI 仍主要依赖自身已有的 WebSocket / 轮询状态。

因此会出现：

- 后台服务已经拿到了新事件
- 前台 ViewModel 暂时还没有同步到这条事件
- 用户点开通知或切回 App 时，会话列表和会话页保持旧状态

## 目标

- 用户回到 App 前台时，UI 必须主动与 hub 同步一次
- 用户点击通知进入会话时，目标会话应立即显示最新消息
- 不要求等待用户手动退出重进

## 方案

推荐采用最简单、最稳的修复：

- 在 App 回到前台时主动拉取一次 `bootstrap`
- 在收到通知点击 intent 时，也主动触发一次刷新
- 刷新完成后再更新当前 UI 状态

这样可以避免让前台 UI 完全依赖旧的实时连接状态，也不需要引入更重的跨进程共享状态机制。

## 非目标

- 本轮不引入 Room、本地事件缓存数据库或 ContentProvider 同步
- 本轮不做服务到 UI 的进程间事件总线
- 本轮不改协议

## 验收标准

- Android 后台收到通知后，点击通知进入 App，会话页可立即看到对应新消息
- 不需要手动杀进程或重启 App
- 使用本机 Android 模拟器完成通知到 UI 的闭环自测
