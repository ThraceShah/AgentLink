# Android 首次连接失败恢复需求

## 背景

当前 Android 客户端已经具备 HTTP 轮询回退，但仍存在一个恢复缺口：

- 如果首次 `bootstrap` 就失败
- `connectWithFallback()` 会抛错
- 但失败时没有保留可重试的 `repository`
- 后续轮询虽然启动了，实际上没有可用目标可继续拉取

这会导致用户在首次连接失败后，即使网络稍后恢复，客户端也不能自动恢复。

## 目标

让 Android 客户端在首次连接失败后，仍能保留本次尝试使用的 hub 配置，并允许 HTTP 轮询继续重试。

## 范围

包含：

- 连接候选创建后即保留为当前 `repository`
- 轮询成功后自动清除连接错误
- 轮询成功后自动更新 agent 列表和时间线

不包含：

- 复杂指数退避
- 多 hub 配置管理
- 后台长连接服务

## 验收标准

- 首次 `bootstrap` 失败后，轮询仍会继续重试
- 网络恢复后，客户端可在不重启 App 的情况下恢复 agent 列表
- 轮询成功后，之前的连接错误提示会被清除
