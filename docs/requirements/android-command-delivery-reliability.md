# Android 命令投递可靠性需求

## 背景

当前 Android 客户端已经可以加载 agent 列表、展示会话和产物，但在模拟器联调中仍存在残留问题：会话页中的快捷命令点击后，未稳定观察到命令事件写入 hub 时间线，也未稳定确认 agent 已收到命令。

该问题的根因尚未完全定位，但从现象上已经可以确认 Android 侧缺少足够的连接状态可观测性，并且命令发送路径没有针对 WebSocket 尚未就绪的场景做保护。

## 目标

为 Android 客户端补齐最小必要的连接状态管理和命令发送保护，确保：

- 用户能看到当前与 hub 的实时连接状态。
- WebSocket 尚未建立完成时，不会静默丢失命令。
- 连接建立后，等待中的命令可以自动发送。
- 调试过程中可以通过 `logcat` 明确判断连接是否打开、命令是否排队、命令是否真正发送。

## 范围

本次仅覆盖 Android 客户端内部可靠性增强，不调整 hub 协议，不引入新的后端依赖。

包含：

- WebSocket 连接状态建模
- 命令排队与连接后刷新
- 连接失败日志
- UI 中的连接状态展示

不包含：

- 自动重连退避策略
- 推送通知
- 后台常驻服务
- 复杂离线缓存

## 验收标准

- 启动应用后，UI 能展示当前连接状态。
- 在连接未就绪时发送命令，不会被静默丢弃。
- 连接建立后，排队命令会被自动发送。
- `logcat` 中可以看到连接打开、命令排队、命令发送、连接失败等关键日志。
- 在模拟器环境中，至少一次成功观察到 `user_command` 事件进入 hub 时间线。
